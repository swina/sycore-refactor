# SY.CORE — Sound Engine · Roland S-1 Adaptive Sound Generator

> **Component:** `ResultsPanel.vue`  
> **Role:** Central sound design workspace — preset identity, real-time parameter control, modulation, and performance integration  
> **Audience:** Musicians, sound designers, producers, live performers

---

## What Is the Sound Engine?

The Sound Engine panel is the heart of SY.CORE. It bridges the gap between the Roland S-1 hardware synthesizer and modern software intelligence — displaying the current sound, exposing every controllable parameter in real time, and giving performers the tools to shape, modulate, and perform sounds that are generated by the AI engine or recalled from the library.

Every parameter change made in this panel sends an immediate MIDI CC to the Roland S-1 hardware. The panel is the sound.

## Section 1 — Sound Identity Header

### The Hardware Display

The identity block is styled as a hardware LCD screen with glass reflection and scanline overlays. It shows:

| Element | Description |
|---------|-------------|
| **Category icon** | Emoji mapped to the sound's type (🎛️ synth, 🎹 pad/piano, ⚡ lead, 🔊 bass, 🥁 drum, etc.) |
| **Index + Name** | `#12 SUPERSAW DRIFT` — history position + editable sound name |
| **Unsaved indicator** | `* name` prefix when there are uncommitted changes |
| **Category label** | Neon-green MIDI-monospace text (e.g. `LEAD`) |
| **Poly badge** | `Mono`, `Unison`, `Poly`, or `Chord` — derived from `polyMode` parameter |
| **SEQ badge** | Violet `SEQ` chip — appears when this sound has a linked Step Sequencer pattern |

**Editing the name:** Click the name to open an inline text input. Press Enter or click away to save.

### Poly Modes

| polyMode value | Label | Description |
|---------------|-------|-------------|
| 0 | Mono | Single voice, last-note priority |
| 1 | Unison | All voices play the same note (orange badge) |
| 2 | Poly | Standard polyphony |
| 3 | Chord | All voices trigger together |

## Section 2 — Actions (Column 3)

### Engine A/B Switch

A circular button toggles between two independent sound variants stored in the same preset:

- **A (neon green):** Primary engine variant (`aVariant`)
- **B (violet):** Alternative variant (`bVariant`) — disabled/greyed if not present

Both variants share the same preset name and metadata but have completely independent parameter sets. This enables instant live switching between two complementary sounds — verse/chorus, dry/wet, lead/pad.

**MIDI learn:** Right-click → maps to `engine_ab` param name (CC or Note).

### Core Action Buttons

| Button | Color | Action |
|--------|-------|--------|
| **💾 Save** | Emerald | Persists preset to Firestore (auth required) |
| **📋 Copy** | Sky blue | Copies all parameter data as JSON to clipboard |
| **♡ Favorite** | Rose | Toggles favorite flag — fills heart icon when active |
| **↺ Regenerate** | Neon (AI) | Re-generates the sound using the AI engine (keeps current category) |
| **⊞ Live Pad** | Violet | Exports this sound's CC values to the next empty Live Set slot |

### Add to Live Pad

Captures a snapshot of the current sound's parameters and writes them into `S1_LIVESET_SOUNDS` (localStorage). The sound is mapped through the configured Live Set parameters and stored as raw CC values. If all 16 slots are full, a "full" feedback message appears for 2.5 seconds.

## Section 3 — Performance Modulation Controls

All modulation controls sit in a second row of the actions column, positioned below the core buttons.

### LFO 1 and LFO 2

Each LFO has a two-part pill button:

```
[LFO 1]  [⚙]      [LFO 2]  [⚙]
```

- **Left part:** Toggles the LFO on/off → calls `lfoStore.toggleLfo(1 or 2)` → neon-cyan when active
- **Right part (⚙):** Opens the LFO panel (`isLfo1Open` / `isLfo2Open`)
- **MIDI learn:** Right-click left part → `lfo1_active` / `lfo2_active`

### Velocity Modulation (VEL)

```
[VEL]  [⚙]
```

- **VEL:** Enables/disables velocity-to-parameter mapping. When disabled, restores original parameter values.
- **⚙:** Opens the Velocity Map panel (`isVelocityMapOpen`)
- **MIDI learn:** Right-click VEL → `vel_active`

### Arpeggiator (ARP)

```
[ARP]  [⚙]
```

- **ARP:** Toggles `arpStore.arpEnabled` → neon-cyan when active
- **⚙:** Opens the Arpeggiator panel (`isArpOpen`)
- **MIDI learn:** Right-click ARP → `arp_active`

### Sequencer Controls

```
[▶ / ■ Play Sequence] [AUTO]        [ListMusic icon]
```

| Control | Action |
|---------|--------|
| **▶ Play Sequence** | Dispatches `toggle-sequencer` event → starts/stops the Step Sequencer |
| **■ (when playing)** | Same button, square icon while playing (neon green when active) |
| **AUTO** | Toggles `seqAutoStart` — when ON, the sequencer auto-starts on the first MIDI note-on |
| **ListMusic icon** | Opens/closes the Step Sequencer panel |

**Visual states of the ListMusic button:**
- Open: Amber background
- Closed + linked sequence: Violet background
- Closed + no sequence: Neutral

**MIDI learn:** Right-click Play Sequence → `seq_play_stop`

## Section 4 — Navigation Bar

### History Navigation (◁ ▷)

Two circular arrow buttons navigate through the preset history list:
- **◁ Previous:** Go to an older preset in the filtered history
- **▷ Next:** Go to a newer preset in the filtered history

These are hidden when there are unsaved changes (to prevent accidental navigation away from modified data).

### Category Tabs

| **⊞ GRID** | Shows all parameter categories at once in compact grid view |
| **FLOW** | Virtual summary category — key parameters from across all sections |
| **OSCILLATOR** | Oscillator mix and waveform controls |
| **LFO** | LFO waveform, rate, depth, modulation routing |
| **ENV** | ADSR amplitude envelope |
| **FILTER** | Filter cutoff, resonance, filter envelope |

Active category tabs are color-coded to their section color with a glow shadow.

**MIDI learn:** Right-click any tab → assigns a CC/Note to switch to that category (`ui_cat_FLOW`, `ui_cat_FILTER`, etc.).

## Section 6 — Parameter Control Types

### Horizontal Slider (default)

Most parameters use drag-to-edit horizontal sliders:

```
CUTOFF                                     74
[████████████████████░░░░░░░░░░░░░░░░░░░░░░]
```

- **Drag left/right** to change value
- **Arrow keys** (↑↓←→) to nudge ±1
- **Value range** is strictly clamped to the hardware's min/max per parameter
- **Color** matches the category color (e.g. orange for FILTER, blue for LFO)
- **Last-modified highlight:** A neon-green ring with pulse glow appears on the most recently changed parameter

### Vertical Slider (`SLIDER_V` type)

Used for parameters that benefit from up/down metaphor (e.g. envelope stages):

```
  ATTACK  127
    │
    │███
    │███
    │███
    └───
```

Drag up/down on the track. Fill rises from bottom.

### Switch (Toggle)

Binary on/off parameters:

```
[Key Trig]                        [ON]
[Key Trig]                        [OFF]
```

Click anywhere on the card to toggle. Active state uses the category color with a soft glow.

### Multi-option Selector (`MULTI` type)

Parameters with discrete named options (e.g. LFO waveform, chorus mode):

```
LFO WAVE                          TRI
[SIN] [TRI] [SAW] [SQ] [RND]
```

Each option is a button. The active option is highlighted with the category color. Options without labels (just numeric indices) display as numbered buttons.

## Section 7 — Sound Generation Engine (AI)

### How Generation Works

When no sound is loaded, the panel shows a "Generate Sound" call-to-action. When collapsed with a sound loaded, a large circular Generate button fills the panel, animated with a rotating neon ring border.

```
         ╭──────────────────────╮
        ╱                        ╲
       │     ⚡ GENERATE SOUND    │
       │        (AI engine)       │
        ╲                        ╱
         ╰──────────────────────╯
```

Clicking **Generate** calls `presetStore.generate()`. The AI engine:
1. Randomly selects or respects the current category/type filter
2. Selects parameter ranges from `S1_TYPES[category]` (see section 9)
3. Creates a preset with values within those type-specific ranges
4. Sets it as the current preset and sends all CCs to the Roland S-1

**Regenerate:** The action button (↺) in the header calls `presetStore.generate(true)` — regenerates in the same category.

### Preview

The **Play** button (when `hasLinkedSequence` is false) triggers a brief ascending C-major arpeggio preview through the current Roland S-1 settings:

```
Notes: C4 → E4 → G4 → C5 → G4 → E4 → C4
Timing: 280ms per note × BPM scale
Gate: 75% of step duration
```

This uses `midiStore.sendNoteOn` / `sendNoteOff` with `MidiSource.UI` so the notes are routed to the hardware without being echoed back as inputs.

## Section 8 — Real-Time Visualizers

Each parameter category has a dedicated real-time visualizer that responds to parameter changes immediately.

| Category | Visualizer | Renders |
|----------|-----------|---------|
| **FLOW** | `SignalFlowVisualizer` | Signal path diagram through all active modules |
| **OSCILLATOR** | `OscMixerVisualizer` | Stacked waveform mix (SAW, SQ, SUB, NOISE, LFO) |
| **LFO** | `WaveformVisualizer` | Animated LFO waveform at current rate |
| **ENV** | `AdsrEnvelope` | ADSR envelope curve (A, D, S, R) |
| **FILTER** | `FilterEnvelope` | Filter response curve (cutoff position + resonance peak) |
| **EFX** | `EfxMixerVisualizer` | 3D-style bar graph (delay, reverb, chorus levels) |

All visualizers are wrapped in a **hardware LCD frame** with glass reflection and scanline overlays — the same visual language as the identity block.

### Engineering Notes (FLOW panel only)

Below the Signal Flow visualizer, a "patch notes" card allows sound designers to annotate each sound:

- Click anywhere on the notes area to enter edit mode
- **Ctrl+Enter / ⌘+Enter** to save
- **Esc** to cancel without saving
- Notes are persisted with the preset in `patchNotes` field

## Section 10 — Sound Type Profiles

The AI generation engine uses pre-defined parameter ranges per sound category. Each type constrains the random generation to musically appropriate zones.

| Type | Character | Oscillator emphasis | Filter | Env | Effects |
|------|-----------|---------------------|--------|-----|---------|
| **pad** | Warm, sustained | High SAW, light SQ | Low-mid cutoff, low res | Slow attack, high sustain | Heavy reverb + chorus |
| **lead** | Bright, articulate | SAW dominant | Mid-high cutoff | Fast attack, long sustain | Moderate reverb |
| **key** | Percussive, tonal | SAW + SQ | Open cutoff | Instant attack, fast decay, low sustain | Light reverb |
| **bass** | Deep, punchy | High SAW + SQ | Low cutoff, mid res | Fast attack, mid sustain | Minimal FX |
| **acid** | Resonant, driving | SAW/SQ alternating | Variable cutoff, very high res | Fast | Light delay |
| **strings** | Lush, evolving | Heavy SAW | Open, low res | Slow attack, high sustain | Reverb + light delay |
| **brass** | Bright, brassy | SAW + SQ | Mid-high, mid-high res | Medium attack | Reverb + light chorus |
| **percussion** | Transient, rhythmic | Mixed waveforms + Noise | Variable | Zero sustain, fast | Variable |
| **organ** | Full, continuous | SAW + SQ mix | Open | Instant attack, full sustain | Chorus |
| **orchestra** | Grand, rich | Heavy SAW + SQ | Open | Slow attack, high sustain | Heavy reverb + chorus |
| **experimental** | Unpredictable | All ranges open | Extreme | All ranges | Max FX |
| **ai** | Unconstrained | Full 0–127 all | Full 0–127 | Full 0–127 | Full 0–127 |

## Section 11 — MIDI Learn System

Every parameter control and every action button supports right-click MIDI learn:

1. **Right-click** any slider, switch, multi-button, or action pill
2. The MIDI learn context menu opens, showing the param name
3. Move a controller on any connected MIDI device
4. The mapping is saved to `midiMappings` in the mapping store

**Orange dot indicator:** While a MIDI learn session is active for a specific param, a small pulsing orange dot appears at the top-right corner of that control's card.

**Last-modified highlight:** When a parameter is changed by incoming MIDI CC, a neon green ring with a pulse glow animation highlights it for a few seconds — providing real-time visual feedback of what the hardware is touching.

## Section 12 — Collapse Modes

### Collapsed Controls

Clicking **Hide Controls** (or the slider icon tab) collapses the parameter section. The panel shows only the header and nav bar. A large circular **Generate** button fills the collapsed space, surrounded by animated audio waveform bars when any audio is playing.

The waveform bars cycle through four colors (neon green, fuchsia, orange, cyan) and animate at different rates — creating a live audio visualizer in the background of the button.

### Preset Index

The `#N` number shown before the sound name indicates its position in the reverse-chronological history. `#1` is always the most recent sound. As more sounds are generated or recalled, the index updates automatically.

## Section 13 — Workflow Examples

### Sound Design Workflow

1. Click **Generate** → AI creates a sound (e.g. `DARK RESONANCE` in `bass`)
2. Click the **FILTER** tab → see the FilterEnvelope visualizer
3. Drag the **Cutoff** slider to taste — the curve updates live, CC 74 is sent
4. Right-click **Resonance** → learn a knob on your hardware controller
5. Tweak live with the controller — the orange dot shows the mapping is active
6. Click **💾 Save** to persist with your changes

### Live Performance Workflow

1. Load a sound with a linked **SEQ** pattern
2. Enable **AUTO** — sequencer will auto-start on first incoming note
3. Play a note → sequencer fires, pattern transposes to played pitch
4. Toggle **A/B** mid-performance for instant variation
5. Enable **LFO 1** for additional movement without reloading the sound
6. Use **◁ ▷** nav arrows to browse to the next sound mid-set

### AI Exploration Workflow

1. Open the **Types** panel and select a category (e.g. `acid`)
2. Click **Generate** repeatedly — each press creates a new acid patch within the acid parameter ranges
3. When you find a good base sound, click **♡ Favorite** to flag it
4. Open **OSCILLATOR** tab — adjust the wave mix manually
5. Click **↺ Regenerate** to vary the patch while keeping the category
6. Copy + paste the JSON if you want to experiment in a different tool

## Technical Summary

| Concern | Implementation |
|---------|---------------|
| Parameter read | `getVal(cfg)` → `activeData[name]`, clamped to [min, max] |
| Parameter write | `presetStore.updateFieldValue()` + `midiStore.sendCC()` |
| Drag | `startHDrag` / `startVDrag` — global mousemove/mouseup listeners |
| Keyboard | Arrow keys → `handleKeyNudge` → ±1 nudge |
| MIDI source tag | All UI-originating CCs tagged `MidiSource.UI` to prevent echo |
| Category structure | `configStore.categories` + `midiConfig` joined and ordered |
| FLOW virtual tab | Hardcoded selection of 7 cross-section key parameters |
| Visualizer refresh | Props bound to `activeData` computed — Vue reactivity handles updates |
| History navigation | `presetStore.navigateHistory('prev' | 'next')` |
| Poly mode display | `getVal('polyMode')` → 0=Mono, 1=Unison, 2=Poly, 3=Chord |
