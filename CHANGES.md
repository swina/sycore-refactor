# Changes
 
A running log of new features added to SY.CORE, newest first.

## 2026-10-31

- **Drum Machine: no sample reload on every sequence switch; MIDI OUT ONLY skips audio work; Step Sequencer parked** — every sequence switch (tabs, Drum Machine chain at each bar, Chord Prog drum FOLLOW at each section) re-fetched and re-decoded all 11 samples, with no cache: CPU and memory piled up during long playback until the browser crashed. The engine now keeps decoded samples by URL (LRU, 64), skips a pad that already has that sample and shares loads still in progress. With **MIDI OUT ONLY** on, a switch loads no samples and sets no FX, and the step cursor isn't drawn (the Drum Machine only sends MIDI notes); turning it off loads the current sequence's sounds again. The old **Step Sequencer** (`StepSequencer.vue`) isn't mounted and its buttons are hidden (toolbar, Home, Main page) behind `STEP_SEQUENCER_ENABLED` in `constants/features.ts`; its store and data are untouched. `lib/drum-engine.js` (`loadSample()`), `DrumMachine.vue`, `SynthApp.vue`, `ResultsPanel.vue`, `HomeView.vue`, `MainPage.vue`. Branch: `master`

- **Virtual Device: collapsible Controls, key / chord / tempo on the LCD** — the **Controls** panel folds away from its header (▸ Controls · CH n · 12), remembered across sessions. The LCD has a new bottom row (16 px values), like the toolbar: **Key** of the track playing in the Tracks Player, **Chord** the Chord Prog plays now, and the tempo (**BPM** of the playing track, else the global BPM). `--` when there's none. `VirtualDeviceView.vue`, new `composables/usePlayerTrackInfo.js` (listens to `player-state-sync`). Branch: `master`

- **DECK > Chord Prog: MIDI Learn on slots A–H, CHORD / ARP, Chain ON / OFF** — right-click → MIDI Learn on the DECK's Chord Prog card: the **A–H** pads (`cp_slot_<i>`, the same params as the Chord Prog Sequencer's slots, so a mapping learned in one works in both), **CHORD / ARP** (`cp_mode`) and **Chain ON / OFF** (`cp_chain`). A CC button (momentary or toggle, auto-detected) or a note flips CHORD / ARP and Chain at every press. A dot on each control shows learning (orange) / mapped (teal); the MIDI Learn conflict dialog names them (`Chord Prog · Slot C`…). `DeckChordProgSummary.vue`, `useMidiCCListener.js`, `lib/midi-learn-conflicts.ts`; tests: `tests/unit/composables/cp-deck-learn.test.ts`. Branch: `master`

- **Virtual Device: preset count in TYPE Category** — in Category the LCD's `· n/N` next to the category showed the category's number among the bank's categories, read as a preset count. It now shows the current preset's position among the presets of its category and how many that category has (e.g. `Pads · 3/12`; `-/12` when the preset isn't in the open bank). `P0285` stays the position in the whole bank. The Program Change panel publishes `pcBrowse.catIndex` / `catTotal`. `VirtualDeviceView.vue`, `MidiDeviceProgramChangePanel.vue`, `lib/pc-browse.ts`. Branch: `master`

- **Virtual Device: the mapped controls go out only from a pad** — the controls' saved CC values are sent to the device only when one of the 8 pads (saved sounds per MIDI channel) is clicked or pressed from a controller. PRESET ▼▲, a CATEGORY change (knob, button, UI dial) and TYPE never send them; a preset / category change made within the 150 ms between a pad's preset and its CCs now cancels those CCs, so they can't land on the new preset. `useVirtualDeviceStore.ts` (`cancelCcRecall()` in `stepPreset()`, `selectCategory()`, `recallSound()`); tests: `tests/unit/stores/virtual-device-store.test.ts`. Branch: `master`

- **Virtual Device: CATEGORY on a momentary button steps, never jumps to the last / first category** — a button learned on CATEGORY could get stuck as a knob: once the control had sent any value other than 0 / 127 (a velocity pad, a noisy contact, a test turn), it was a knob for good, so 127 picked the last category and 0 the first. The knob / button kind is now read from how the value moves and corrected as it goes: small steps between values = knob (picks by value), jumps to / from 0 = button. A momentary steps to the next category at every 127 (wrapping from the last to the first) and ignores the 0 on release. `CategoryControlMode` in `lib/virtual-device.ts`, `useMidiCCListener.js`; tests: `tests/unit/composables/vd-category-learn.test.ts`. Branch: `master`

- **Virtual Device: MIDI Learn on TYPE, CATEGORY knob** — right-click the **TYPE** switch → MIDI Learn (`vdp_type:<device>`): a CC button (momentary or toggle, auto-detected) or a note switches All / Category, like a click. In **Category** a **CATEGORY** knob appears under the LCD: it goes through the categories of the bank open in Program Change (in list order); turning it sends the first preset of the category it lands on, and the LCD shows `Category · n/N`. Right-click → MIDI Learn (`vdp_category:<device>`): the controller's knob spreads the categories over 0–127 and a preset is sent only when it enters another category. A **button** works too: a momentary (127 on press, 0 on release), a toggle button or a note goes to the next category at every press and wraps around the list (fast presses go on from the category just asked for). The knob/button kind is detected from what the control sends. The Program Change panel publishes the open bank's categories (`pcBrowse.categories`) and handles `device-pc-category-select`. `VirtualDeviceView.vue`, `useVirtualDeviceStore.ts` (`toggleBrowseScope()`, `categories()`, `selectCategory()`, `setCategoryFromCc()`), `lib/virtual-device.ts`, `useMidiCCListener.js`, `MidiDeviceProgramChangePanel.vue`, `lib/pc-browse.ts`, `types/events.ts`; tests: `tests/unit/stores/virtual-device-store.test.ts`, `tests/unit/lib/virtual-device.test.ts`, `tests/unit/composables/vd-category-learn.test.ts`. Branch: `master`

- **MIDI Learn: ask before taking a control that's already mapped** — learning a controller knob/fader/button that already drives something else used to overwrite or drop the old binding without a word (e.g. a Virtual Device dial's mapping lost when the same knob was learned on a mixer volume, a Program Change panel button or FM-1). Now every learn checks all the MIDI Learn systems — right-click MIDI Learn (Virtual Device controls, mixer, synth params…, also old device-less CC mappings), MIDI Actions, the Program Change panel's buttons and preset-list CC, the FM-1 panel — and if the control is taken a dialog shows what it drives now and the new mapping: **Keep current** (the new learn is dropped) or **Replace** (the old bindings are removed, the new one stored). Re-learning the same function on the same control doesn't ask; several MIDI Actions on one control are still checked by the MIDI Actions mapper itself. `lib/midi-learn-conflicts.ts`, `components/ui/MidiLearnConflictDialog.vue` (in `SynthApp.vue`), `useMappingStore.ts` (`confirmLearnChecked()`), `MidiDeviceProgramChangePanel.vue`, `Fm1EmulatorPanel.vue`, `AppMidiMapper.vue`, `QuickChannelSelector.vue`, `MidiMapContextMenu.vue`, `MidiMappingPanel.vue`, `MidiControllerDesigner.vue`; tests: `tests/unit/stores/midi-learn-conflicts.test.ts`. Branch: `master`

- **Dev: no doubled MIDI handling after a hot reload** — editing `midi-service.ts` (or a module it imports) in `npm run dev` hot-reloaded it into a second `MidiService` listening to the inputs next to the old one: every incoming message was handled twice (doubled Thru, notes echoed on release). The module now declines hot updates, so Vite does a full page reload. Dev only. `midi-service.ts`. Branch: `master`

- **MIDI Flow: FADER SNAP per input device** — cheap faders (e.g. on Novation / AKAI controllers) often stop at 1–3 instead of 0, or below 127. The device card in MIDI Flow has a new **FADER SNAP** setting (OFF, ±1…±10): incoming CC values within that many steps of 0 / 127 become 0 / 127. It applies to MIDI Thru and to everything driven by CC (MIDI Learn mappings such as mixer volumes, Virtual Device controls, synth params); the MIDI Monitor still shows the value the controller really sent. Off by default — keep it off on devices with relative (endless) encoders. `faderDeadZone` on the device registration (`types/midi.ts`), `snapFaderValue()` in `midi-broadcast.ts`, `handleIngress()` in `midi-service.ts`, `MidiWizardFlow.vue`; tests: `tests/unit/midi/fader-dead-zone.test.ts`. Branch: `master`
